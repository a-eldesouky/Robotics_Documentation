# Probabilistic Path Planning with Markov Decision Processes

## 1. Introduction

Classical path planning algorithms usually assume that robot actions are deterministic. If a planner commands the robot to move forward, the model often assumes that the robot will move forward exactly as intended. This assumption is useful for algorithms such as A*, Uniform Cost Search, grid-based search, roadmap planning, and many combinatorial planners, but it does not fully represent real robotic motion.

In real environments, robot motion is uncertain. A rover may slip on loose terrain, drift because of localization error, fail to execute a motion command accurately, or be pushed away from its intended direction by rough ground. This uncertainty becomes especially important when the environment contains hazards. A path that is short in a deterministic grid may be dangerous if a small execution error can push the robot into a pond, cliff, obstacle, or unsafe region.

Probabilistic path planning addresses this problem by explicitly modeling uncertainty. Instead of assuming that each action leads to one guaranteed next state, it models actions as probability distributions over possible next states. This allows the planner to reason not only about distance, but also about risk.

A natural framework for this type of planning is the **Markov Decision Process**, or **MDP**. In an MDP, the robot knows the environment, the possible actions, the rewards or penalties associated with states, and the probabilities of moving from one state to another. The result of solving an MDP is not simply a single path, but a **policy**: a rule that tells the robot what action to take from every possible state. 

---

## 2. Why Deterministic Planning Is Not Enough

Consider an exploratory rover that must travel from a drop-off location to a goal location. The rover is operating in hazardous terrain, and the final path should be safe enough for humans to follow. A deterministic path planner can find a valid path through the terrain, but it may choose a path that passes close to a dangerous region because the planner only evaluates the nominal motion.

For example, a deterministic planner might find the shortest path around a pond. On paper, the path is valid. However, if the rover has a chance of slipping sideways while moving, then passing near the pond could be extremely risky. The path is geometrically valid but probabilistically unsafe.

One possible workaround is to inflate the robot footprint or inflate obstacles so that the planner keeps extra clearance. This can help in some cases, but it can also make the planning problem overly conservative. In narrow environments, inflated obstacles may block otherwise feasible paths, and the planner may lose completeness.

Another approach is to assign negative costs to dangerous regions. This encourages the planner to avoid them, but it still does not fully model motion uncertainty. The planner may know that a pond is bad, but it does not explicitly reason about the probability of accidentally entering it.

Probabilistic path planning solves this more directly. It asks:

> Given uncertain motion, terrain cost, hazards, and a goal, what action should the robot take in every state to maximize expected long-term reward?

This shifts the problem from finding the shortest path to finding the safest and most valuable behavior under uncertainty.

## 3. Core Concepts

### 3.1 States

A **state** describes the condition or position of the robot at a given time. In a grid-based path planning problem, each cell can be treated as a state.

For example:

[
s = (x, y)
]

In a more realistic robot system, the state may include position, orientation, velocity, battery level, sensor status, or task progress.

In the recycling robot example, the state may include the robot’s battery level, such as:

[
S_t = \text{high}
]

This means that at time step (t), the robot’s battery is high.

---

### 3.2 Actions

An **action** is something the robot can choose to do from a state.

In a grid world, actions may be:

[
A = {\text{up}, \text{down}, \text{left}, \text{right}}
]

For a recycling robot, actions may include:

* search for cans,
* wait,
* recharge,
* move to another location.

For a mobile robot, actions are often movement commands. In a simplified 4-connected grid, the robot may move one cell up, down, left, or right.

---

### 3.3 Rewards

A **reward** expresses how desirable or undesirable a state is.

In probabilistic path planning, rewards are used to encode objectives and risks. Common choices include:

| State Type                   | Example Reward | Meaning                           |
| ---------------------------- | -------------: | --------------------------------- |
| Normal flat terrain          |           (-1) | Small cost for time or movement   |
| Difficult terrain / mountain |           (-3) | Higher traversal cost             |
| Hazard / pond                |          (-50) | Large penalty for danger          |
| Goal                         |         (+100) | Large positive reward for success |

The reward values do not need to be infinite. In fact, rewards in MDPs are typically finite. The goal is to make hazardous states unattractive while still allowing the planner to compare risks numerically.

A small negative reward for ordinary movement encourages the robot to reach the goal efficiently. A larger negative reward for difficult terrain encourages the robot to avoid slow or costly regions. A very large negative reward for hazards encourages safe behavior. A large positive reward for the goal attracts the robot toward successful task completion. 

---

### 3.4 Transition Model

The **transition model** describes the probability of reaching a next state after taking an action.

It is written as:

[
T(s,a,s')
]

This means:

[
T(s,a,s') = P(s' \mid s,a)
]

In words:

> The probability of reaching state (s') after taking action (a) from state (s).

This is the core idea that makes MDPs useful for probabilistic planning. The robot does not assume that an action always succeeds. Instead, each action has multiple possible outcomes.

For example, if the rover tries to move forward one cell:

| Outcome                   | Probability |
| ------------------------- | ----------: |
| Moves forward as intended |       (0.8) |
| Moves left instead        |       (0.1) |
| Moves right instead       |       (0.1) |

If the robot attempts to move into a wall, it may remain in its current cell. This is common in grid-world MDPs: invalid motion does not move the robot, but it still consumes an action and may still receive the corresponding state cost.

---

### 3.5 The Markov Assumption

The Markov assumption states that the next state depends only on the current state and current action, not on the full history of how the robot arrived there.

Mathematically:

[
P(s_{t+1} \mid s_t, a_t)
]

The model does not need:

[
s_0, s_1, s_2, \dots, s_{t-1}
]

This assumption simplifies planning. Once the robot is in a state, the planner only needs to know:

* the current state,
* the chosen action,
* the transition model.

The full past trajectory is ignored.

---

## 4. Markov Decision Process Definition

A **Markov Decision Process** is defined by:

[
MDP = (S, s_0, A, T, R)
]

Where:

| Symbol      | Meaning          |
| ----------- | ---------------- |
| (S)         | Set of states    |
| (s_0)       | Initial state    |
| (A)         | Set of actions   |
| (T(s,a,s')) | Transition model |
| (R(s))      | Reward function  |

The transition model gives the probability of reaching a state (s') from a state (s) after executing action (a). The reward function gives the reward or penalty associated with states.

In probabilistic path planning, the robot usually knows all components of the MDP: the states, actions, transition probabilities, and rewards. This is different from many reinforcement learning problems, where the agent may not know the transition model or reward function in advance and must learn them through interaction. 

---

## 5. MDP Planning vs Reinforcement Learning

MDPs appear in both path planning and reinforcement learning, but the assumptions are different.

| Aspect           | MDP Path Planning                 | Reinforcement Learning               |
| ---------------- | --------------------------------- | ------------------------------------ |
| Transition model | Known                             | Often unknown                        |
| Reward function  | Known                             | Often learned or discovered          |
| Environment      | Usually modeled before planning   | Learned through interaction          |
| Objective        | Compute optimal policy from model | Learn optimal policy from experience |
| Method type      | Model-based planning              | Trial-and-error learning             |

In probabilistic path planning, the robot already has a model of the world. It knows the consequences and probabilities of its actions. Therefore, it can compute a policy before execution.

In reinforcement learning, the agent may initially know only its available actions and current state. It may have to discover which actions are good or bad by interacting with the environment.

## 6. Example: Recycling Robot

A recycling robot drives around an environment and collects cans. Its objective is to collect as many cans as possible while avoiding failure, such as running out of battery and becoming stranded.

The robot may have battery states such as:

[
S = {\text{high}, \text{low}}
]

It may have actions such as:

[
A = {\text{search}, \text{wait}, \text{recharge}}
]

Suppose the robot is in the high-battery state:

[
S_t = \text{high}
]

It chooses the action:

[
A_t = \text{search}
]

The action is non-deterministic. There may be:

* a (70%) probability that the battery remains high,
* a (30%) probability that the battery drops to low.

So the action “search” does not guarantee a single outcome. It defines a probability distribution over possible next states.

This captures the essence of MDP planning: actions influence the future, but they do not fully determine it.

---

## 7. Example: Mobile Robot in Hazardous Terrain

Consider a mobile robot navigating a grid environment. The robot starts in the top-left cell and must reach a goal in the bottom-right cell.

The map contains:

* flat land,
* mountains,
* a pond,
* a goal.

The mountains represent difficult terrain. Moving through them takes more effort or time. The pond is a hazard; entering it may destroy the robot.

A deterministic A* planner on a 4-connected grid might choose the shortest route, such as:

```text
Right → Right → Down → Down → Right
```

or another equally short route:

```text
Right → Right → Down → Right → Down
```

This path may be geometrically optimal, but it passes close to the pond. Because the robot’s motion is uncertain, there is a chance it may accidentally slip into the pond. Therefore, the shortest path may not be the safest path.

An MDP planner considers both the reward map and the transition probabilities. It may choose a longer route if that route has a lower probability of catastrophic failure.

This is the key practical advantage of probabilistic path planning.

---

## 8. Policy: The Solution of an MDP

The solution to an MDP is called a **policy**.

A policy is written as:

[
\pi(s) = a
]

It maps each state to an action.

For example:

| State            | Policy Action         |
| ---------------- | --------------------- |
| Cell ((0,0))     | Move right            |
| Cell ((0,1))     | Move down             |
| Cell ((1,1))     | Move right            |
| Cell near hazard | Move away from hazard |

An **optimal policy** is written as:

[
\pi^*(s)
]

The optimal policy chooses the best action from each state to maximize expected long-term reward.

Unlike a single path, a policy gives the robot a decision rule for every possible state. This is extremely useful under uncertainty. If the robot slips into an unintended neighboring cell, it can still look up the best action from that new state and continue safely.

---

## 9. Expected Reward

In deterministic planning, evaluating an action is simple. If the robot moves into a flat cell, the reward might be (-1). If it moves into a mountain cell, the reward might be (-3).

In probabilistic planning, the robot may not end up in the intended cell. Therefore, the planner computes the **expected reward** of an action.

Suppose the robot is in a mountain cell and chooses to move right. The transition model is:

| Possible Result                   | Probability | Reward |
| --------------------------------- | ----------: | -----: |
| Moves right into flat land        |       (0.8) |   (-1) |
| Moves upward into mountain        |       (0.1) |   (-3) |
| Hits wall and remains in mountain |       (0.1) |   (-3) |

The expected reward is:

[
E[R] = 0.8(-1) + 0.1(-3) + 0.1(-3)
]

[
E[R] = -0.8 - 0.3 - 0.3
]

[
E[R] = -1.4
]

So although the intended target is a flat cell with reward (-1), the expected reward is worse because the robot may accidentally remain in or move into a mountain cell.

This is the main difference between deterministic and probabilistic action evaluation. The planner evaluates the whole distribution of outcomes, not only the intended outcome. 

---

## 10. Utility / State Value

The **utility** of a state, also called the **state value**, measures how attractive that state is with respect to the goal.

It answers the question:

> If the robot starts from this state and follows a policy, how much total reward should it expect to receive?

The utility of a state under policy (\pi) is:

[
U^\pi(s)
========

E
\left[
\sum_{t=0}^{\infty}
R(s_t)
\mid
\pi, s_0=s
\right]
]

Where:

| Symbol     | Meaning                                 |
| ---------- | --------------------------------------- |
| (U^\pi(s)) | Utility of state (s) under policy (\pi) |
| (E)        | Expected value                          |
| (R(s_t))   | Reward at time step (t)                 |
| (\pi)      | Policy followed by the robot            |
| (s_0=s)    | The robot starts from state (s)         |

The utility is the expected sum of rewards the robot receives when starting from a state and following the policy until the task ends. A state with high utility is desirable. A state with low utility is undesirable or risky. 

---

## 11. Utility as an Iterative Concept

The utility equation can be understood recursively.

Start with:

[
U^\pi(s)
========

E
\left[
R(s_0) + R(s_1) + R(s_2) + \dots
\mid
\pi, s_0=s
\right]
]

The first reward comes from the current state. The remaining rewards come from future states visited by following the policy.

So the utility can be separated into:

[
U^\pi(s)
========

R(s)
+
U^\pi(s')
]

This simplified form shows the intuition:

> The value of the current state equals the immediate reward plus the value of the next state.

In probabilistic environments, there may be multiple possible next states, so the future utility must be averaged according to transition probabilities.

The utility depends on the policy. If the policy changes, the future sequence of states changes, and therefore the utility values also change. 

---

## 12. Discounting

In many planning problems, future rewards are discounted. This means that immediate rewards matter more than rewards far in the future.

The discounted utility is:

[
U^\pi(s)
========

E
\left[
\sum_{t=0}^{\infty}
\gamma^t R(s_t)
\mid
\pi, s_0=s
\right]
]

Where:

[
0 \leq \gamma \leq 1
]

The parameter (\gamma) is the **discount factor**.

| Discount Factor  | Behavior                                                 |
| ---------------- | -------------------------------------------------------- |
| (\gamma = 0)     | Only immediate reward matters                            |
| (0 < \gamma < 1) | Future rewards matter less than immediate rewards        |
| (\gamma = 1)     | Future rewards are valued equally with immediate rewards |

In the simplified lesson example, (\gamma = 1), meaning future actions are considered just as important as present actions. This simplifies manual calculation.

In practical robotic planning, (\gamma < 1) is often used because the future is uncertain. A robot should usually prioritize reliable near-term outcomes while still considering long-term mission success. 

---

## 13. Bellman Optimality Equation

The Bellman equation is the mathematical foundation of value iteration.

For an optimal policy, the utility of a state is:

[
U(s)
====

R(s)
+
\gamma
\max_a
\sum_{s'}
T(s,a,s')
U(s')
]

This equation contains four important ideas:

1. **Immediate reward**
   [
   R(s)
   ]
   The value of being in the current state.

2. **Future utility**
   [
   U(s')
   ]
   The value of possible next states.

3. **Transition probability**
   [
   T(s,a,s')
   ]
   The probability of reaching each next state.

4. **Best action selection**
   [
   \max_a
   ]
   The robot chooses the action that gives the highest expected utility.

The summation computes the expected utility of taking an action:

[
\sum_{s'} T(s,a,s')U(s')
]

The maximization selects the best action:

[
\max_a \sum_{s'} T(s,a,s')U(s')
]

So the Bellman equation says:

> The best value of a state is its immediate reward plus the discounted expected value of the best action’s possible future outcomes.

---

## 14. Determining the Optimal Policy

The optimal policy is:

[
\pi^*(s)
========

\arg\max_a
\sum_{s'}
T(s,a,s')
U(s')
]

This means:

> Choose the action (a) that maximizes expected future utility.

The policy is extracted after computing the utilities. For every state, the planner evaluates all available actions and selects the action with the highest expected utility.

For states adjacent to the goal, the best action is usually obvious: move toward the goal. For states farther away, the best action may be less intuitive because the robot must account for terrain costs, hazards, and uncertain motion.

A useful manual strategy is to reason backward from the goal. States next to the goal receive high utility because they can reach the goal quickly. States near hazards may receive lower utility because their future outcomes include a risk of entering dangerous regions. This process continues until every state is assigned a best action. 

---

## 15. Value Iteration Algorithm

For small examples, it may be possible to reason manually about the best action in each state. In larger environments, this becomes impractical. Value Iteration automates the process.

Value Iteration computes the utility of every state by repeatedly applying the Bellman update.

### 15.1 Initialization

Start by assigning an arbitrary utility value to every state, commonly zero:

[
U(s) = 0
]

for all:

[
s \in S
]

The initial values do not need to be correct. Value Iteration improves them over repeated updates.

---

### 15.2 Iterative Update

For every state, update its utility using:

[
U(s)
====

R(s)
+
\gamma
\max_a
\sum_{s'}
T(s,a,s')
U(s')
]

Each iteration propagates information backward from rewarding or dangerous states. Goal states influence their neighbors, those neighbors influence their neighbors, and so on.

With enough iterations, the utilities converge to stable values.

---

### 15.3 Algorithm

```text
Initialize U(s) = 0 for all states

Repeat until convergence:

    U_old = U

    For each state s in S:

        U(s) = R(s) + γ max_a Σ_s' T(s, a, s') U_old(s')

Return U
```

After computing the utilities, extract the policy:

```text
For each state s:

    π*(s) = argmax_a Σ_s' T(s, a, s') U(s')
```

The final result is the optimal policy.

---

## 16. Convergence

Value Iteration repeats until the utility values stop changing significantly.

One common convergence test is the Root Mean Square error between the old utility values and the new utility values:

[
RMS
===

\sqrt{
\frac{1}{|S|}
\sum_s
\left(
U(s) - U'(s)
\right)^2
}
]

The algorithm stops when:

[
RMS(U,U') < \epsilon
]

Where:

| Symbol     | Meaning                     |   |                  |
| ---------- | --------------------------- | - | ---------------- |
| (U)        | Current utility estimate    |   |                  |
| (U')       | Previous utility estimate   |   |                  |
| (          | S                           | ) | Number of states |
| (\epsilon) | Small convergence threshold |   |                  |

A smaller (\epsilon) gives a more accurate solution but requires more iterations. A larger (\epsilon) converges faster but may produce a less accurate policy.

Value Iteration converges to the optimal utilities regardless of the initial utility values, although poor initialization can affect how quickly it converges. 

---

## 17. Parameters and Tuning

### 17.1 Rewards

Rewards strongly shape the robot’s behavior.

| Parameter                    | Effect                                 |
| ---------------------------- | -------------------------------------- |
| More negative movement cost  | Encourages shorter paths               |
| Less negative movement cost  | Allows longer, safer paths             |
| More negative hazard penalty | Stronger hazard avoidance              |
| Larger goal reward           | Stronger attraction to the goal        |
| Higher mountain penalty      | Avoids rough terrain more aggressively |

If the hazard penalty is too small, the robot may accept dangerous routes. If it is too large, the robot may become overly conservative.

---

### 17.2 Transition Probabilities

The transition model controls how much uncertainty the planner considers.

Example:

```text
Forward succeeds: 0.8
Slip left:        0.1
Slip right:       0.1
```

If the success probability is high, the planner behaves more like a deterministic planner. If the slip probabilities increase, the planner becomes more cautious around hazards and obstacles.

A robot operating on smooth indoor floors may use a high success probability. A rover operating on loose soil, sand, mud, or rocks should use a more uncertain transition model.

---

### 17.3 Discount Factor

The discount factor (\gamma) balances immediate and future reward.

| (\gamma) | Planning Behavior           |
| -------: | --------------------------- |
|      Low | Greedy, short-term behavior |
|   Medium | Balanced behavior           |
|     High | Strong long-term planning   |

For episodic navigation tasks with a clear goal, a relatively high (\gamma) is common because the robot should care about reaching the goal. However, using (\gamma < 1) can help represent uncertainty about the future and improve convergence properties.

---

### 17.4 Convergence Threshold

The threshold (\epsilon) determines when Value Iteration stops.

| (\epsilon) | Effect                |
| ---------: | --------------------- |
|    Smaller | More accurate, slower |
|     Larger | Faster, less accurate |

In robotics, this is an engineering trade-off. If the policy is used offline, a small threshold may be acceptable. If planning must run online or frequently, a larger threshold may be used to reduce computation.

---

## 18. Edge Cases and Limitations

### 18.1 Large State Spaces

MDPs become expensive when the number of states grows. A small grid is easy to solve, but a high-resolution map with orientation, velocity, battery level, and uncertainty can become very large.

For example, a state may include:

[
s = (x, y, \theta, v, b)
]

Where:

* (x, y): position,
* (\theta): orientation,
* (v): velocity,
* (b): battery level.

Adding each variable increases the state space dramatically.

---

### 18.2 Continuous Environments

Basic Value Iteration is usually explained on discrete states. Real robots operate in continuous spaces. To use MDPs directly, the environment is often discretized.

Discretization introduces trade-offs:

| Resolution  | Advantage     | Disadvantage   |
| ----------- | ------------- | -------------- |
| Fine grid   | More accurate | More expensive |
| Coarse grid | Faster        | Less precise   |

A coarse grid may miss narrow passages or important terrain details. A fine grid may be computationally expensive.

---

### 18.3 Reward Design Is Not Always Obvious

The behavior of an MDP planner depends heavily on the reward function. Poorly chosen rewards can create undesirable behavior.

For example:

* if the step cost is too high, the robot may choose risky shortcuts;
* if the hazard penalty is too low, the robot may pass too close to danger;
* if the goal reward is too low, the robot may not be strongly motivated to reach the goal;
* if mountain penalties are too large, the robot may take unnecessarily long detours.

Reward tuning is not just mathematical; it is an engineering design process.

---

### 18.4 Known Transition Model Assumption

MDP planning assumes that the transition model is known. In real systems, this may not be perfectly true.

The robot may not know exactly how often it slips on each terrain type. Transition probabilities may need to be estimated from:

* experiments,
* simulation,
* terrain classification,
* historical robot logs,
* learned motion models.

If the transition model is inaccurate, the computed policy may be suboptimal or unsafe.

---

### 18.5 Full Observability Assumption

The basic MDP assumes that the robot knows its current state. In real robotics, localization is uncertain. If the robot is not sure where it is, the problem becomes a **Partially Observable Markov Decision Process**, or **POMDP**.

A POMDP is more realistic but also significantly more complex.

---

## 19. Practical Robotics Insights

### 19.1 MDP Planning Produces Behavior, Not Just a Path

A deterministic planner usually outputs a sequence of waypoints or actions:

```text
Right → Right → Down → Down → Right
```

An MDP outputs a policy:

```text
If in state A, move right.
If in state B, move down.
If in state C, move away from hazard.
```

This is valuable because the robot can recover from uncertain outcomes. If it slips into a different state, it already knows the best action from that state.

---

### 19.2 Risk Is Modeled Explicitly

Obstacle inflation approximates uncertainty geometrically. MDPs model uncertainty probabilistically.

This allows the planner to answer questions such as:

* What is the expected penalty of moving near a pond?
* Is a shorter route worth the probability of failure?
* Is rough terrain acceptable if it avoids a severe hazard?
* Should the robot take a longer but safer route?

This makes MDPs suitable for risk-aware navigation.

---

### 19.3 Costmaps and MDPs Are Conceptually Related

In classical navigation, a costmap assigns traversal costs to regions. MDPs also assign rewards or penalties to states.

The difference is that an MDP combines those costs with transition uncertainty. A high-cost cell is bad, but a cell near a high-cost hazard may also become unattractive if there is a significant probability of slipping into it.

---

### 19.4 MDPs Are Useful for Terrain-Aware Planning

For a rover, terrain affects both cost and uncertainty.

Flat terrain may have:

```text
low traversal cost
high motion success probability
```

Mountainous terrain may have:

```text
higher traversal cost
lower motion success probability
higher slip probability
```

Hazardous terrain may have:

```text
very large negative reward
mission failure risk
```

This makes MDPs more expressive than planners that only optimize path length.

---

## 20. Complete Value Iteration Example in Python

The following example implements a simple grid-world MDP with uncertain movement. It uses Value Iteration to compute utilities and then extracts the optimal policy.

```python
import math
from typing import Dict, Tuple, List

State = Tuple[int, int]

# Grid symbols:
# F = flat land
# M = mountain
# P = pond / hazard
# G = goal
grid = [
    ["F", "F", "F", "F"],
    ["F", "M", "P", "F"],
    ["F", "M", "F", "G"],
]

rows = len(grid)
cols = len(grid[0])

rewards = {
    "F": -1.0,
    "M": -3.0,
    "P": -50.0,
    "G": 100.0,
}

actions = ["UP", "DOWN", "LEFT", "RIGHT"]

delta = {
    "UP": (-1, 0),
    "DOWN": (1, 0),
    "LEFT": (0, -1),
    "RIGHT": (0, 1),
}

# For each intended action, define possible actual outcomes.
# Example: trying to move UP succeeds with 0.8,
# but may slip LEFT or RIGHT with 0.1 each.
transition_outcomes = {
    "UP": [("UP", 0.8), ("LEFT", 0.1), ("RIGHT", 0.1)],
    "DOWN": [("DOWN", 0.8), ("RIGHT", 0.1), ("LEFT", 0.1)],
    "LEFT": [("LEFT", 0.8), ("DOWN", 0.1), ("UP", 0.1)],
    "RIGHT": [("RIGHT", 0.8), ("UP", 0.1), ("DOWN", 0.1)],
}


def is_valid(state: State) -> bool:
    r, c = state
    return 0 <= r < rows and 0 <= c < cols


def move(state: State, action: str) -> State:
    r, c = state
    dr, dc = delta[action]
    next_state = (r + dr, c + dc)

    # Bumping into a wall keeps the robot in the same state.
    if not is_valid(next_state):
        return state

    return next_state


def is_terminal(state: State) -> bool:
    r, c = state
    return grid[r][c] in ["G", "P"]


def state_reward(state: State) -> float:
    r, c = state
    return rewards[grid[r][c]]


def expected_utility(
    state: State,
    action: str,
    utilities: Dict[State, float],
) -> float:
    total = 0.0

    for actual_action, probability in transition_outcomes[action]:
        next_state = move(state, actual_action)
        total += probability * utilities[next_state]

    return total


def value_iteration(
    gamma: float = 0.95,
    epsilon: float = 1e-4,
    max_iterations: int = 10_000,
) -> Dict[State, float]:
    utilities = {
        (r, c): 0.0
        for r in range(rows)
        for c in range(cols)
    }

    for iteration in range(max_iterations):
        old_utilities = utilities.copy()
        squared_error_sum = 0.0

        for r in range(rows):
            for c in range(cols):
                state = (r, c)

                if is_terminal(state):
                    utilities[state] = state_reward(state)
                else:
                    best_future_utility = max(
                        expected_utility(state, action, old_utilities)
                        for action in actions
                    )

                    utilities[state] = (
                        state_reward(state)
                        + gamma * best_future_utility
                    )

                error = utilities[state] - old_utilities[state]
                squared_error_sum += error * error

        rms_error = math.sqrt(squared_error_sum / (rows * cols))

        if rms_error < epsilon:
            print(f"Converged after {iteration + 1} iterations.")
            break

    return utilities


def extract_policy(
    utilities: Dict[State, float],
) -> Dict[State, str]:
    policy = {}

    for r in range(rows):
        for c in range(cols):
            state = (r, c)

            if is_terminal(state):
                policy[state] = "TERMINAL"
                continue

            best_action = max(
                actions,
                key=lambda action: expected_utility(
                    state,
                    action,
                    utilities,
                ),
            )

            policy[state] = best_action

    return policy


def print_utilities(utilities: Dict[State, float]) -> None:
    for r in range(rows):
        row_values = []
        for c in range(cols):
            row_values.append(f"{utilities[(r, c)]:8.2f}")
        print(" ".join(row_values))


def print_policy(policy: Dict[State, str]) -> None:
    arrows = {
        "UP": "↑",
        "DOWN": "↓",
        "LEFT": "←",
        "RIGHT": "→",
        "TERMINAL": "■",
    }

    for r in range(rows):
        row_values = []
        for c in range(cols):
            row_values.append(arrows[policy[(r, c)]])
        print(" ".join(row_values))


if __name__ == "__main__":
    utilities = value_iteration(gamma=0.95, epsilon=1e-4)
    policy = extract_policy(utilities)

    print("\nUtilities:")
    print_utilities(utilities)

    print("\nPolicy:")
    print_policy(policy)
```

### 21.5 Expected Utility

```python
def expected_utility(state, action, utilities):
    total = 0.0

    for actual_action, probability in transition_outcomes[action]:
        next_state = move(state, actual_action)
        total += probability * utilities[next_state]

    return total
```

This function computes:

[
\sum_{s'} T(s,a,s')U(s')
]

It evaluates an action by considering every possible actual outcome.

```python
utilities[state] = (
```

R(s)

U(s')

The planner computes the immediate reward plus the discounted best expected future utility.

## 22. Conclusion

Probabilistic path planning extends classical planning by explicitly modeling uncertainty. Instead of assuming that every action succeeds exactly as commanded, it treats actions as probability distributions over possible next states.

This is essential for real robots operating in risky environments. A deterministic shortest path may pass dangerously close to a hazard, while an MDP-based planner can choose a safer path by considering the probability of motion error.

The key concepts are:

* an MDP is defined by states, actions, transition probabilities, rewards, and an initial state;
* the transition model captures non-deterministic motion;
* rewards encode goals, costs, terrain difficulty, and hazards;
* utility measures the expected long-term value of a state;
* the optimal policy maps each state to the best action;
* Value Iteration computes utilities using the Bellman equation;
* the final policy is robust because it tells the robot what to do from every state, not only along one planned path.

Classical planning asks:

> What is the shortest valid path?

Probabilistic planning asks:

> What is the best action to take from every state, given uncertainty, risk, and long-term reward?

That difference makes MDPs a powerful tool for risk-aware robotic navigation.
