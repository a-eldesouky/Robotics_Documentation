# A* Search in Robotics: From Theory to Practical ROS2 Implementation

---

## 1. Introduction

Path planning is a fundamental problem in robotics: how can a robot move from a start position to a goal while avoiding obstacles and minimizing cost?

In real robotic systems—such as mobile robots using ROS 2 and occupancy grids—this problem must be solved efficiently, reliably, and in real time. Classical uninformed search algorithms like Breadth-First Search (BFS) and Uniform Cost Search (UCS) explore the environment blindly, often expanding unnecessary regions.

A* Search addresses this limitation by introducing **goal-directed intelligence** through heuristics. It is one of the most widely used algorithms in robotics, autonomous driving, and navigation systems due to its balance between optimality and efficiency.

---

## 2. Core Concepts

### 2.1 Path Planning in Grid Maps

Robotic navigation commonly operates on a **discrete grid representation** (e.g., occupancy grid):

* Each cell represents free space or an obstacle
* The robot moves between neighboring cells
* The goal is to find the **shortest collision-free path**

---

### 2.2 From Uninformed to Informed Search

Uninformed search (e.g., BFS, UCS):

* No knowledge of goal location
* Explores in all directions
* Computationally expensive

Informed search (A*):

* Uses a **heuristic** to estimate distance to goal
* Prioritizes promising directions
* Reduces unnecessary exploration

---

### 2.3 The Key Idea of A*

A* evaluates nodes using:

[
f(n) = g(n) + h(n)
]

Where:

* **g(n)** → actual cost from start to node
* **h(n)** → estimated cost from node to goal
* **f(n)** → total estimated cost of the path through node

👉 Intuition:

* ( g(n) ) → “How far have I come?”
* ( h(n) ) → “How far do I think I still need to go?”
* ( f(n) ) → “How good is this path overall?”

---

## 3. Mathematical Foundations

### 3.1 Manhattan Distance (Grid-Based Heuristic)

[
h(n) = |x_{goal} - x| + |y_{goal} - y|
]

* Assumes 4-directional movement
* Common in occupancy grid maps

---

### 3.2 Euclidean Distance

[
h(n) = \sqrt{(x_{goal} - x)^2 + (y_{goal} - y)^2}
]

* Straight-line distance
* Suitable for continuous motion

---

### 3.3 Chebyshev Distance

[
h(n) = \max(|x_{goal} - x|, |y_{goal} - y|)
]

* Supports diagonal motion
* Used in 8-connected grids

---

### 3.4 Heuristic Properties

To guarantee optimality, the heuristic must satisfy:

#### Admissibility

[
h(n) \leq \text{true cost to goal}
]

* Never overestimates

#### Consistency (Triangle Inequality)

[
h(n) \leq cost(n, n') + h(n')
]

* Ensures stable and efficient search

---

## 4. System Model in Robotics

### 4.1 Occupancy Grid Representation

Robots typically use:

* `nav_msgs/OccupancyGrid`
* Values:

  * `0` → free
  * `>0` → occupied

---

### 4.2 Coordinate Systems

Planning requires conversions between:

* **World coordinates** (meters)
* **Grid coordinates** (cells)

[
x_{grid} = \frac{x_{world} - x_{origin}}{resolution}
]

---

### 4.3 Motion Model

In grid-based A*:

* Movement is discrete
* Common directions:

  * 4-connected: up, down, left, right
  * 8-connected: includes diagonals

---

## 5. A* Algorithm

### 5.1 High-Level Steps

1. Initialize a priority queue (open set)
2. Insert start node
3. Loop:

   * Select node with lowest ( f(n) )
   * If goal reached → stop
   * Expand neighbors
   * Update costs and parent links
4. Reconstruct path

---

### 5.2 Priority Queue Behavior

Nodes are ordered by:

[
f(n) = g(n) + h(n)
]

This ensures:

* Short paths are favored (low ( g(n) ))
* Goal-directed movement (low ( h(n) ))

---

## 6. Code-Level Implementation (ROS 2 A* Planner)

A practical implementation in ROS 2 integrates A* into a node that subscribes to a map and a goal, then publishes a path.

``` cpp
#include <queue>
#include <vector>
#include <algorithm>
#include <memory>

#include "a_star_planning/a_star_planner.hpp"
#include "rmw/qos_profiles.h"

namespace a_star_planning
{

AStarPlanner::AStarPlanner() : Node("a_star_node")
{
    tf_buffer_ = std::make_unique<tf2_ros::Buffer>(get_clock());
    tf_listener_ = std::make_shared<tf2_ros::TransformListener>(*tf_buffer_);

    rclcpp::QoS map_qos(10);
    map_qos.durability(RMW_QOS_POLICY_DURABILITY_TRANSIENT_LOCAL);

    map_sub_ = create_subscription<nav_msgs::msg::OccupancyGrid>(
        "/map",
        map_qos,
        std::bind(&AStarPlanner::mapCallback, this, std::placeholders::_1));

    pose_sub_ = create_subscription<geometry_msgs::msg::PoseStamped>(
        "/goal_pose",
        10,
        std::bind(&AStarPlanner::goalCallback, this, std::placeholders::_1));

    path_pub_ = create_publisher<nav_msgs::msg::Path>(
        "/a_star/path",
        10);

    map_pub_ = create_publisher<nav_msgs::msg::OccupancyGrid>(
        "/a_star/visited_map",
        10);
}

void AStarPlanner::goalCallback(
    const geometry_msgs::msg::PoseStamped::SharedPtr pose)
{
    if (!map_) {
        RCLCPP_ERROR(get_logger(), "No map received!");
        return;
    }

    visited_map_.data =
        std::vector<int8_t>(
            visited_map_.info.height * visited_map_.info.width,
            -1);

    geometry_msgs::msg::TransformStamped map_to_base_tf;

    try {
        map_to_base_tf = tf_buffer_->lookupTransform(
            map_->header.frame_id,
            "base_footprint",
            tf2::TimePointZero);
    } catch (const tf2::TransformException & ex) {
        RCLCPP_ERROR(
            get_logger(),
            "Could not transform from map to base_footprint");
        return;
    }

    geometry_msgs::msg::Pose start_pose;
    start_pose.position.x = map_to_base_tf.transform.translation.x;
    start_pose.position.y = map_to_base_tf.transform.translation.y;
    start_pose.orientation = map_to_base_tf.transform.rotation;

    auto path = plan(start_pose, pose->pose);

    if (!path.poses.empty()) {
        RCLCPP_INFO(get_logger(), "Shortest path found!");
        path_pub_->publish(path);
    } else {
        RCLCPP_WARN(get_logger(), "No path found to the goal.");
    }
}

nav_msgs::msg::Path AStarPlanner::plan(
    const geometry_msgs::msg::Pose & start,
    const geometry_msgs::msg::Pose & goal)
{
    std::vector<std::pair<int, int>> explore_directions = {
        {-1, 0},
        {1, 0},
        {0, -1},
        {0, 1}
    };

    std::priority_queue<
        GraphNode,
        std::vector<GraphNode>,
        std::greater<GraphNode>
    > pending_nodes;

    std::vector<GraphNode> visited_nodes;

    GraphNode start_node = worldToGrid(start);
    GraphNode goal_node = worldToGrid(goal);

    start_node.heuristic =
        manhattanDistance(start_node, goal_node);

    pending_nodes.push(start_node);

    GraphNode active_node;

    while (!pending_nodes.empty() && rclcpp::ok()) {
        active_node = pending_nodes.top();
        pending_nodes.pop();

        if (active_node == goal_node) {
            break;
        }

        for (const auto & dir : explore_directions) {
            GraphNode new_node = active_node + dir;

            if (
                std::find(
                    visited_nodes.begin(),
                    visited_nodes.end(),
                    new_node) == visited_nodes.end()
                &&
                poseOnMap(new_node)
                &&
                map_->data.at(poseToCell(new_node)) == 0
            ) {
                new_node.cost = active_node.cost + 1;
                new_node.heuristic =
                    manhattanDistance(new_node, goal_node);
                new_node.prev =
                    std::make_shared<GraphNode>(active_node);

                pending_nodes.push(new_node);
                visited_nodes.push_back(new_node);
            }
        }

        visited_map_.data.at(poseToCell(active_node)) = -106;
        map_pub_->publish(visited_map_);
    }

    nav_msgs::msg::Path path;
    path.header.frame_id = map_->header.frame_id;

    while (active_node.prev && rclcpp::ok()) {
        geometry_msgs::msg::Pose pose = gridToWorld(active_node);

        geometry_msgs::msg::PoseStamped pose_stamped;
        pose_stamped.header.frame_id = map_->header.frame_id;
        pose_stamped.pose = pose;

        path.poses.push_back(pose_stamped);
        active_node = *active_node.prev;
    }

    std::reverse(path.poses.begin(), path.poses.end());

    return path;
}

double AStarPlanner::manhattanDistance(
    const GraphNode & node,
    const GraphNode & goal_node)
{
    return std::abs(node.x - goal_node.x)
         + std::abs(node.y - goal_node.y);
}

bool AStarPlanner::poseOnMap(const GraphNode & node)
{
    return node.x < static_cast<int>(map_->info.width)
        && node.x >= 0
        && node.y < static_cast<int>(map_->info.height)
        && node.y >= 0;
}

GraphNode AStarPlanner::worldToGrid(
    const geometry_msgs::msg::Pose & pose)
{
    int grid_x = static_cast<int>(
        (pose.position.x - map_->info.origin.position.x)
        / map_->info.resolution);

    int grid_y = static_cast<int>(
        (pose.position.y - map_->info.origin.position.y)
        / map_->info.resolution);

    return GraphNode(grid_x, grid_y);
}

geometry_msgs::msg::Pose AStarPlanner::gridToWorld(
    const GraphNode & node)
{
    geometry_msgs::msg::Pose pose;

    pose.position.x =
        node.x * map_->info.resolution
        + map_->info.origin.position.x;

    pose.position.y =
        node.y * map_->info.resolution
        + map_->info.origin.position.y;

    return pose;
}

unsigned int AStarPlanner::poseToCell(const GraphNode & node)
{
    return map_->info.width * node.y + node.x;
}
}
```

### 6.1 Node Architecture

The planner node:

* Subscribes to:

  * `/map` → occupancy grid
  * `/goal_pose` → target
* Publishes:

  * `/a_star/path` → planned path
  * `/a_star/visited_map` → visualization

---

### 6.2 Core Data Structures

#### Priority Queue (Open Set)

```cpp
std::priority_queue<GraphNode, std::vector<GraphNode>, std::greater<GraphNode>>
```

* Stores frontier nodes
* Sorted by lowest ( f(n) )

---

#### GraphNode Structure (Conceptually)

Each node contains:

* Grid position (x, y)
* Cost ( g(n) )
* Heuristic ( h(n) )
* Pointer to previous node

---

### 6.3 Heuristic Computation

```cpp
return abs(node.x - goal_node.x) + abs(node.y - goal_node.y);
```

* Implements Manhattan distance
* Efficient for grid-based motion

---

### 6.4 Neighbor Expansion

```cpp
std::vector<std::pair<int, int>> explore_directions = {
    {-1, 0}, {1, 0}, {0, -1}, {0, 1}
};
```

* Defines movement model
* Only 4-directional expansion

---

### 6.5 Cost Update

```cpp
new_node.cost = active_node.cost + 1;
new_node.heuristic = manhattanDistance(new_node, goal_node);
```

* Increment path cost
* Recompute heuristic

---

### 6.6 Path Reconstruction

* Uses backtracking via `prev` pointer
* Reverses path to start → goal order

## 7. Parameters and Tuning

### 7.1 Heuristic Choice

* Manhattan → fast, grid-based
* Euclidean → realistic, continuous
* Chebyshev → diagonal motion

---

### 7.2 Resolution

* Higher resolution → more accuracy, slower planning
* Lower resolution → faster, less precise

---

### 7.3 Movement Model

* 4-connected → simpler, longer paths
* 8-connected → shorter paths, more branching

---

## 8. Edge Cases and Limitations

### 8.1 Missing Cost Updates

If the algorithm does not update nodes when a better path is found:

* It may produce **suboptimal paths**

---

### 8.2 Improper Visited Handling

Marking nodes as visited too early:

* Prevents discovering better paths later

---

### 8.3 Lack of Efficient Data Structures

Using linear search for visited nodes:

* Leads to poor scalability

---

### 8.4 Heuristic Misguidance

If the heuristic:

* Overestimates → breaks optimality
* Is weak → behaves like UCS

---

### 8.5 Environmental Limitations

A* may struggle when:

* The optimal path initially moves away from the goal
* The map is very large (memory usage increases)

---

## 9. Practical Insights

### 9.1 A* as a Balance

A* combines:

* Optimality (like UCS)
* Direction (like greedy search)

---

### 9.2 Heuristic Quality Matters

* Strong heuristic → faster search
* Weak heuristic → more exploration

---

### 9.3 Real Robotics Considerations

In production systems:

* A* is often extended:

  * Hybrid A*
  * D* / D* Lite
* Integrated with:

  * Costmaps
  * Inflation layers
  * Dynamic obstacles

---

### 9.4 Engineering Trade-offs

| Aspect             | Trade-off      |
| ------------------ | -------------- |
| Accuracy           | vs Speed       |
| Heuristic strength | vs Optimality  |
| Grid resolution    | vs Computation |

---

## 10. Conclusion

A* Search is a cornerstone algorithm in robotics path planning, offering a powerful balance between optimality and efficiency. By combining actual path cost with heuristic estimation, it intelligently navigates toward the goal while minimizing unnecessary exploration.

Its effectiveness depends heavily on:

* The choice of heuristic
* Proper cost handling
* Efficient data structures

In real-world robotic systems, A* serves as a foundation upon which more advanced planners are built, making a deep understanding of its principles essential for designing robust navigation solutions.

Mastering A* is not just about implementing the algorithm—it is about understanding how **cost, heuristics, and system constraints interact** to produce reliable and efficient robot behavior.
